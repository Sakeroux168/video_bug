## 项目是什么

- 给公司非技术员工用的 Windows 便携 EXE（Electron + React + node:sqlite）：在内置浏览器登录抖音 / 快手 / 小红书，按关键词、话题、作者主页批量抓公开视频元数据，下载视频与封面，FFmpeg 统一成 1080×1920，按设置归档并可导出 CSV。
- 员工在用的是 `视频爬取工具-快手多平台-2026-09-08.exe`（抖音 + 快手）。新 EXE 必须用新文件名，不覆盖旧版。
- 项目详细背景、架构、红线清单：`docs/视频爬取交接文档.md`（§10 红线必须遵守）。

## 长期有效的决定

- 抓取方式只保留「页面自己请求、程序旁听响应」一条路，不生成签名、不代发请求。
- **先抓真机接口再写解析器，不照公开资料写**（快手 GraphQL 的教训：网页端实际是 `/rest/v/search/feed`、`/rest/v/profile/feed`）。
- 快手不返回评论数，`comments` 保持 `null`，不映射成 0。
- 小红书：用户要求**必须能下载视频文件**，所以走两段式（列表收候选 → 逐条导航详情页 → 旁听详情响应取播放地址）。
- 小红书 `xsec_token` 是短期令牌：只在任务内存里用，不落库、不进日志；库里作品链接不带 token。
- 小红书网页「视频」筛选：09-08 曾否决；09-28 Codex 按真机调研改为用 CDP 真实 hover 点筛选面板，失败则回退，解析层仍兜底丢图文。
- 不抄 MediaCrawler 等非商业许可代码；许可兼容项目（如 `xpzouying/xiaohongshu-mcp`，Apache-2.0）只参考思路。
- 不绕过验证码，不做账号池、代理池、高并发；验证弹窗一律暂停等人工处理。
