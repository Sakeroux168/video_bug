## 项目是什么

- Windows 桌面工具（Electron + React + node:sqlite）：在内置浏览器登录抖音 / 快手 / 小红书，按关键词、话题、作者主页批量抓公开视频元数据，下载视频与封面，FFmpeg 统一成 1080×1920，按设置归档并可导出 CSV。
- **2026-09-29 起用途改变**：用户即将离职，员工手里是很旧的版本，以后不再给员工发新版。本工具现在**只给用户个人学习使用**，用户打算开源。原来为「员工交付」定的规矩（不覆盖员工 EXE、给员工写使用说明等）不再是约束；判断许可证、风险时按「个人、非商业、学习」来算。
- 用户的抓取量时大时小。
- 项目许可证目前是 MIT + Commons Clause（源码可用，禁止出售）。如果以后要改成 OSI 开源（例如 GPL-3.0），要由用户决定。
- 项目详细背景、架构、红线清单：`docs/视频爬取交接文档.md`（§10 红线仍然适用，第 12 条「不覆盖稳定 EXE」除外，那条是为员工定的）。

## 长期有效的决定

- 抓取方式默认是「页面自己请求、程序旁听响应 / 读页面注水状态」，不生成签名。
- **2026-09-29 决定：小红书加「稳妥 / 快速」开关，建任务时选。** 稳妥 = 在窗口里逐条打开详情页（目标每条约 3 秒）；快速 = 用登录态在后台直接取详情页 HTML、解析注水状态（借鉴 XHS-Downloader 的思路，自己实现）。在快速模式下，「不代发请求」这条规矩由用户放开。直接调签名接口（MediaCrawler 的思路）暂不做，留作学习课题。量大时靠间隔、分批、验证码暂停来控制风控，不靠提速。
- **先抓真机接口再写解析器，不照公开资料写**（快手 GraphQL 的教训：网页端实际是 `/rest/v/search/feed`、`/rest/v/profile/feed`）。
- 快手不返回评论数，`comments` 保持 `null`，不映射成 0。
- 小红书：用户要求**必须能下载视频文件**，所以走两段式（列表收候选 → 逐条导航详情页 → 旁听详情响应取播放地址）。
- 小红书 `xsec_token` 是短期令牌：只在任务内存里用，不落库、不进日志；库里作品链接不带 token。
- 小红书网页「视频」筛选：09-08 曾否决；09-28 Codex 按真机调研改为用 CDP 真实 hover 点筛选面板，失败则回退，解析层仍兜底丢图文。
- 许可证结论（2026-09-29 核对原文）：MediaCrawler（非商业学习许可证）允许个人学习时使用，但**没有授予公开发布的权利**，所以代码不能搬进这个公开仓库，只借鉴思路；XHS-Downloader（GPL-3.0）和本项目的 Commons Clause 冲突，同样只借鉴思路；`xpzouying/xiaohongshu-mcp`（Apache-2.0）可以参考，它也是逐条打开详情页。
- 不绕过验证码，不做账号池、代理池、高并发；验证弹窗一律暂停等人工处理。
