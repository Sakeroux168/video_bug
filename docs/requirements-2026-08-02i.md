# 需求文档：第十轮验收修复（筛选自动触发修复/目标数量自由/测试按钮移位）

**日期**: 2026-08-02
**状态**: 待开发（无歧义）
**上一轮**: 第九轮全绿。用户实测发现：到底显示「暂时没有更多了」却不自动触发筛选续爬（手动点测试按钮才成功）；很多次爬不完 200 条。

## 1. 根因（已代码确认）

筛选续爬的触发判断位于**停滞分支**内（`buildStopDecision` 连续 5 轮空数据才进入）。但到底后接口仍零星返回 `解析9→剩1`——每轮 1-2 条新数据使 `emptyRounds` 清零、`lastFetchedAt` 重置 → 停滞分支永远到不了 → 触发条件被锁死；同时目标 200 靠每轮 1-2 条永远爬不满。

## 2. 核心诉求（3 条）

### ① 筛选自动触发修复

- 触发判断**移出停滞分支**：`run` 循环每轮都检查——
  - `filters.douyinFilter?.enabled && task.type==='keyword' && !filterApplied`
  - 且（`findBottomText()` 命中到底文案 **或** `Date.now() - lastFetchedAt > 15000`）
  - 满足即触发 `applyDouyinFilter`（沿用成功重置计数/失败 notice 兜底/FILTER_BUSY 重试逻辑）。
- 每轮检查 findBottomText 的开销可接受（一次 executeJavaScript）；可每 2 轮查一次（实现者定，注释说明）。
- **验收**：到底显示「暂时没有更多了」→ 自动触发筛选（无需手动）；15 秒无新视频同样触发。

### ② 目标数量 1-1000 自由设置

- FilterForm：`target` 输入 `min=1 max=1000`，校验 `target >= 1 && target <= 1000`（错误文案「目标数量需在 1-1000 之间」）；默认仍 200。
- scheduler 侧 target 默认 200 不变（`filters.targetCount ?? 200`）。
- **验收**：填 50/300/1000 都能建任务；<1 或 >1000 报错。

### ③ 手动测试按钮移入筛选条件模块

- 「手动测试筛选」按钮从 App 头部移到 **FilterForm 的「搜索到底后用抖音筛选续爬」配置区**（4 个下拉旁或下方）；App 头部移除。
- `debug:testFilter` IPC 不变；按钮行为/防重不变。
- **验收**：按钮出现在筛选续爬配置区，点击行为同前。

## 3. 范围

### 做

- App.tsx：移除头部测试按钮
- tests/scheduler.test.ts：触发不再依赖停滞分支（新测试：有零星数据时到底文案命中仍触发）
