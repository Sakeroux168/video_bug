# 快手适配器实施计划

## 目标

在不改变现有抖音、下载、视频标准化和归档行为的前提下，为桌面端增加快手关键词、作者和话题任务。快手网页产生的 GraphQL 响应进入现有 `VideoItem → 筛选 → SQLite → Downloader → VideoNormalizer → Organizer` 主链。

## 约束

- 保留抖音现有 `persist:douyin` 登录态；快手使用独立 `persist:kuaishou`。
- 不复制 MediaCrawler、QMediaCrawler、videodl 等非商业或许可证不明确项目的源码。
- 仅解析用户在内置浏览器中正常访问公开页面时产生的响应，不绕过验证码、不维护账号池、不伪造签名。
- 自动测试使用本地固定夹具，不依赖快手在线稳定性。
- 快手短链接只识别并给出明确错误；本阶段不在创建任务时静默联网解析跳转。

## 数据契约

快手适配器输出：

- 作品 ID：`photo.id`
- 标题：`caption`，缺失时回退 `originCaption`
- 作者：`feed.author.id/name`
- 播放地址：优先 `photoUrl`；缺失时从 `videoResource` 中选择 H.264 的最高质量表示，再回退 HEVC
- 封面：`coverUrl`，回退 `coverUrls[0].url`
- 宽高：优先所选视频表示；回退 `videoRatio`
- 时长：毫秒转秒
- 发布时间：毫秒时间戳转 Unix 秒
- 点赞/评论：非负整数；未知评论为 `null`
- 作品页：`https://www.kuaishou.com/short-video/{作品ID}`

## 实施步骤

### 1. 快手适配器与固定夹具

- 新增失败测试覆盖搜索、作者、详情三种 GraphQL 结构。
- 覆盖 H.264 质量选择、HEVC 回退、封面/宽高回退、毫秒转换、真实零评论和未知评论。
- 覆盖作者 URL/裸 ID 解析、短链接拒绝、作品 URL 和主机白名单。
- 实现 `src/main/adapters/kuaishou.ts` 并注册到适配器表。

### 2. 平台化响应路由

- 把页面注入消息从抖音专用命名泛化为平台原始响应消息。
- 由当前任务适配器匹配 URL 和任务类型，不在主进程写死抖音适配器。
- 把“当前任务类型是否接受该接口”下沉到适配器，抖音行为保持不变，快手按 GraphQL `operationName`/响应根字段区分搜索、作者与详情。
- 增加路由与回归测试，确保推荐流不会混入任务。

### 3. 独立登录分区浏览器

- `VideoBrowser` 按适配器切换 BrowserWindow；切平台时销毁当前窗口并用目标 `sessionPartition` 重建。
- 每个平台 Cookie/缓存继续由持久分区保存，切回抖音不丢登录态。
- 标题、首页和作者昵称清洗跟随平台。
- 增加窗口创建、分区切换和重复加载不重建测试。

### 4. 创建任务与界面文案

- 平台下拉显示“抖音 / 快手”。
- 作者输入占位符随平台变化，非法作者输入返回平台对应提示。
- 任务列表显示平台中文名，避免直接展示内部键名。
- 下载请求头使用适配器主页作为 Referer，保持快手 CDN 下载兼容。

### 5. 验证与交付

- 运行快手适配器、浏览器、调度器、IPC 和界面定向测试。
- 运行完整类型检查、全量测试、生产构建、CSS 与许可检查。
- 本机启动开发版，在快手窗口完成页面加载和接口拦截烟测；如需登录或验证码，只提示人工完成，不自动处理。
- 通过后构建新的便携 EXE；保留 2026-09-06 已验收版本作为可用回退。

## 非目标

- 本阶段不抓评论正文，只保存评论数快照。
- 不直接调用需要 OAuth 的快手开放平台接口。
- 不实现小红书；快手验收后进入下一阶段。
- 不保证平台未来改版后永久免维护；字段变化必须通过诊断与夹具更新处理。
