# 多平台、评论与链接、视频标准化及禁止销售许可设计

## 目标

在现有抖音抓取、下载、封面、时长筛选和横竖屏归档基础上增加：

1. 任务视频列表显示评论数和原始作品链接，并可分别复制作品链接、作者名或打开原作品。
2. 新增快手和小红书视频抓取，沿用相同的筛选、下载、封面、归档和删除流程。
3. 使用随包 FFmpeg 把横屏成品规范为 `1920×1080`，竖屏成品规范为 `1080×1920`，不拉伸主体。
4. 源码公开，允许免费使用、修改及利用软件输出赚钱，但禁止出售软件本身、换皮版或修改版。

## 术语与范围

- “评论数”是抓取时平台接口返回的计数快照，不是实时同步数据，也不是抓取评论正文。
- “作品链接”是可在浏览器打开的作品页地址，不是可能过期的 CDN 下载地址。
- 小红书本期只收录视频笔记；纯图文笔记跳过，不进入视频下载任务。
- “禁止销售”针对软件本身、改名版、修改版、打包下载和以软件本体为主要价值的付费服务；允许使用者利用软件抓取、整理或处理自己有权处理的内容并从成果获利。
- 本期不实现验证码绕过、账号池、代理池、高并发轰炸、付费云 API 或自动抓取私人内容。

## 总体架构

现有业务主链保持不变：

`平台浏览器/适配器 → VideoItem → 统一筛选 → SQLite → Downloader → VideoNormalizer → Organizer`

核心模块只消费归一数据，不感知平台字段。每个平台负责自己的登录分区、页面地址、接口特征、原始 JSON 解析和作品链接生成。下载、封面、时长筛选、转码、归档、删除继续复用现有实现。

### 平台隔离

- 抖音：`persist:douyin`
- 快手：`persist:kuaishou`
- 小红书：`persist:xiaohongshu`

浏览器窗口标题、Cookie、缓存、错误日志和登录提示按平台隔离。Cookie 只存在 Electron session 或主进程；不写普通日志，不传给 renderer，不存进任务 JSON。

现有 `VideoBrowser` 从单一抖音窗口泛化为按当前任务加载相应 `PlatformAdapter` 的平台浏览器。仍使用网页自身真实浏览器会话产生请求和签名，主进程只接收已发生的接口响应；不把社区项目中的 Python 浏览器整体塞进 Electron。

## 社区轮子采用原则

### 可以直接复用或借鉴

- 小红书登录、搜索、详情和作者作品优先参考 Apache-2.0 的 [xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 与 MIT 的 [Openweb](https://github.com/imoonkey/openweb)。
- 快手单作品和下载流程可参考 MIT/BSD/Apache 许可实现；实际媒体仍交给现有 Downloader 下载平台返回的原始播放地址。
- [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) 用于核对平台字段、流程和异常场景；其自定义非商用许可证单独审查，不默认复制源码。
- GPL/AGPL 项目可用于研究和行为对照，但代码不合并、不链接、不随 EXE 捆绑，避免与“禁止销售”附加条件冲突。
- 无 LICENSE 的仓库只允许阅读公开行为，不复制、修改或分发其源码。

每个实际采用的文件或组件登记来源仓库、固定提交、许可证、修改说明和随包 NOTICE。平台适配逻辑必须有本项目自己的测试夹具，不能只依赖上游仓库仍然可用。

## 统一视频数据契约

`VideoItem` 增加：

- `comments: number | null`：明确返回时为非负整数；缺失或非法时为 `null`，不能与真实零评论混淆。
- `sourceUrl: string`：作品页地址。

现有 `awemeId` 在数据库物理列暂时保留，避免破坏旧库和唯一索引；代码注释和界面统一称“作品 ID”。各平台仍以 `UNIQUE(platform, aweme_id)` 去重，因此不同平台相同 ID 不冲突。

数据库增量增加 `source_url TEXT`。评论数继续写入 `stats` JSON：

```json
{ "likes": 123, "comments": 45 }
```

旧行没有 `source_url` 时，根据 `platform + aweme_id` 生成标准作品页；无法生成时显示 `—`。旧 `stats` 没有 `comments` 时显示 `—`，不伪装成真实的零评论。

## 任务视频列表

### 列与排序

现有“点赞”旁新增“评论”，支持升降序排序，格式沿用点赞数的万/千缩写。链接不单独占据宽列，避免表格过宽；标题下方以弱化样式显示域名和截断后的作品链接，鼠标悬停显示完整地址。

### 行内操作

每条非过滤视频提供：

- `打开原视频`
- `复制链接`
- `复制作者名`

复制使用主进程受限 IPC 或浏览器 Clipboard API；复制成功提示“链接已复制”或“作者名已复制”，失败显示可理解的错误。按钮必须保持原生 `button/a`，不得破坏现有点行选中、Ctrl/Shift 多选和框选守卫。

打开链接仅允许 `https://` 且主机属于当前平台白名单，拒绝数据库中被污染的其他协议或域名。

## 平台适配器

### 抖音

- 保持当前搜索、作者、话题和播放地址逻辑。
- 评论数读取 `statistics.comment_count`。
- 作品地址为 `https://www.douyin.com/video/{作品ID}`。

### 快手

- 支持关键词搜索、作者主页/作者 ID、作品详情和视频下载。
- 使用独立快手浏览器登录；优先解析网页 GraphQL/接口响应，不依赖易碎的 DOM 元素文本。
- 归一化标题、作者 ID/昵称、播放地址、封面、宽高、毫秒时长、发布时间、点赞数、评论数和作品页地址。
- 分享短链不在纯字符串阶段猜 ID；需要在受控平台浏览器中解析跳转后再执行任务。
- 接口改版、签名失败、登录失效、验证码和限流分别返回明确错误，不静默产生空任务。

### 小红书

- 支持关键词搜索、作者主页/作者 ID、作品详情和视频笔记下载。
- 使用独立小红书浏览器登录；沿用页面自己的 `X-s/X-t/xsec_token` 等会话能力，不在 renderer 保存或拼接签名。
- 只将视频笔记转换为 `VideoItem`；图文笔记计入“已跳过图文”诊断，不计入抓取目标数量。
- 归一化标题、作者 ID/昵称、视频地址、封面、宽高、时长、发布时间、点赞数、评论数和带必要公开查询参数的作品链接。
- `xsec_token` 等可能过期参数只用于打开作品页，不作为永久身份；去重只用稳定笔记 ID。

### 风控与节奏

- 各平台默认并发保持低值，沿用现有滚动间隔、停滞检测和验证码暂停。
- 不自动处理验证码；提示用户在对应平台窗口完成后继续。
- 登录失效时暂停该平台任务，不影响其他平台任务及已下载文件。
- 只抓公开内容；用户负责确保自己对下载和后续使用拥有权限。

## 视频标准化

### 输出规则

- 原始 `height >= width`：竖屏，输出 `1080×1920`。
- 原始 `width > height`：横屏，输出 `1920×1080`。
- 元数据未知：先用现有 ffprobe；仍未知则跳过标准化并归入“未识别”，保留原视频。
- 正方形沿用现有规则，按竖屏输出。
- 已经是目标分辨率、像素宽高比为 1 且编码/封装可兼容时跳过转码，避免无意义损耗。

### 画面策略

默认采用“完整前景 + 同源模糊背景”：

1. 将输入分成背景和前景两路。
2. 背景等比例放大铺满目标画布、居中裁剪，在较低工作分辨率上高斯模糊，再缩放到目标尺寸。
3. 前景等比例缩放到完整装入目标画布，不拉伸、不裁剪。
4. 前景居中叠加到背景，设置 `SAR=1`、`yuv420p`。

不使用简单 `scale=1920:1080` 或 `scale=1080:1920` 拉伸。低分辨率输入的输出画布会达到目标尺寸，但不能创造原片不存在的细节。

### 编码与兼容

- 默认：MP4 + H.264，软件编码 `libx264 -preset medium -crf 20`。
- 音频：有音轨则转 AAC 192 kbps，无音轨正常输出。
- `-movflags +faststart`，保留正常时长和音画同步。
- 可检测 NVIDIA/Intel/AMD H.264 硬件编码器并做短样本能力测试；通过才使用，失败自动回退软件编码。
- 第一版不默认启用 AV1，避免老设备播放兼容性和过慢编码问题。

### 原子处理与失败恢复

1. 下载写入现有视频 `.part`。
2. 完成下载和现有视频校验后，FFmpeg 从原始 `.part` 写入独立 `.normalized.part.mp4`。
3. 对标准化结果再次检查视频流、目标尺寸、文件非空和时长误差。
4. 成功后把标准化临时文件原子改名为最终 MP4，再删除原始 `.part`。
5. FFmpeg 不存在、转码失败、取消或暂停时清理标准化半成品；原始下载通过校验时仍作为最终视频保留，并记录“标准化失败”，不能丢视频。
6. Downloader 只在上述流程结束后标记 `done`，Organizer 不会移动仍在转码的文件。

### 设置

- `统一输出分辨率`：默认开启。
- `保留原视频`：默认关闭。

开启“保留原视频”时，原片以 `${主体名}.original.mp4` 与成品同行移动，数据库增加 `original_path TEXT`。文件管理的视频数量和体积统计只计算成品；程序删除视频时同步删除受管理目录内的原片与封面。归档失败的真实路径和重试标记覆盖视频、封面和原片三者。

## 数据迁移与兼容

- 旧数据库自动增量增加 `source_url`、`original_path`；旧任务、旧视频和旧归档路径继续可读。
- `stats` JSON 解析必须容忍空对象、损坏 JSON、旧 `likes` 单字段及新增字段。
- 新设置均有默认值，旧 `settings.json` 无需手动修改。
- 不移动已正常归档的旧视频，不自动给旧视频转码，不补抓旧评论数；只有新抓取或用户明确重试的条目走新流程。
- 平台展示名称和作品 URL 生成集中在适配器，任务表不得继续硬编码抖音域名。

## 错误与可观察性

- 平台解析得到视频对象但缺关键字段时，记录字段名诊断，不打印 Cookie、签名或完整响应正文。
- 列表显示“登录失效、需要验证、平台限流、解析失败、下载失败、标准化失败”中的明确状态。
- 标准化进度至少显示“等待转码/转码中/已完成/已跳过/失败保留原片”，并可响应现有暂停和取消。
- 评论数未知显示 `—`，真实零评论显示 `0`。
- 复制和打开动作不改变当前行选择状态。

## 测试与验收

### 数据与界面

1. 三个平台夹具都能生成正确作品 ID、作者、链接、点赞、评论、封面、宽高和时长。
2. 旧 `stats` 显示评论未知，新数据的 0 与非零评论正确显示并排序。
3. 复制链接、复制作者名、打开白名单作品页成功；恶意协议/域名被拒绝。
4. 行内按钮不破坏点选、Ctrl/Shift 多选、全选和框选。

### 平台

5. 搜索、作者、详情三种任务按平台使用正确 URL、登录分区和接口模式。
6. 快手/小红书登录失效、验证码、限流和接口改版返回可区分状态。
7. 小红书图文笔记跳过，视频笔记进入统一下载链。
8. 用受控本地响应完成三平台端到端测试，不让自动测试依赖线上平台稳定性。

### 标准化

9. 用真实 FFmpeg 生成横屏、竖屏、正方形、4:3、超宽和低分辨率样本，输出尺寸正确、主体不拉伸、音画时长在容差内。
10. 已符合目标的视频跳过转码；无尺寸、无音轨和旋转元数据样本安全处理。
11. FFmpeg 失败、输出校验失败、暂停、取消和程序退出均不丢失已验证原视频，不残留半成品。
12. 开关“保留原视频”时，原片、成品、封面同组归档、重名、恢复和删除；文件统计不重复计算原片。

### 许可证与发布

13. 发布包包含主许可证、中文解释、NOTICE、商标说明和 FFmpeg 许可证材料。
14. 依赖清单拒绝无许可证或与禁止销售条件不兼容的直接依赖。
15. 全量类型检查、测试、生产构建、CSS 检查及便携 EXE 独立资料启动验收通过后才交付。

## 实施拆分

为降低一次改动风险，按以下顺序实施并分别验收：

1. 评论数、作品链接和复制/打开操作。
2. 视频标准化与可恢复文件生命周期。
3. 许可证、NOTICE、商标和发布检查。
4. 快手适配器。
5. 小红书适配器。

每一阶段都复用同一 `PlatformAdapter`、Downloader 和 Organizer 契约；上一阶段通过全量回归后才进入下一阶段。
