# 时长筛选、封面下载与横竖屏归档设计

## 目标

在不破坏现有任务、设置、登录状态和已归档文件的前提下：

1. 时长筛选增加“30 秒内”和用户自定义秒数范围。
2. 下载视频时同步下载同名封面。
3. 新下载的视频按横竖屏和现有的一分钟内/外规则整理。

## 全局约束

- 不重复造轮子：复用现有 `Downloader`、`safeFilename`、`ensureUniqueName`、`Organizer`、数据库增量迁移和 `findBin('ffprobe')`。
- 不引入与 Node/Electron 现有能力重复的新依赖；优先使用内置 `fetch`、`fs`、`path` 和项目已有 ffprobe 能力。
- 旧数据库必须自动增量升级；旧任务 JSON、旧视频行和旧版数据继续可读。
- 已经归档完成的旧文件不自动搬迁，避免一次升级大批移动用户文件；新下载和之后重新整理的未归档文件使用新目录。

## 时长筛选

### 数据契约

`DurationFilter` 在现有 `all | short | medium | long` 上增加：

- `under30`：视频时长 `<= 30` 秒。
- `custom`：使用 `durationMinSec`、`durationMaxSec` 两个正整数边界。

自定义筛选包含两端，例如 10–20 秒会保留 10、20 以及中间时长的视频。最短时长必须大于等于 1，最长时长必须大于等于最短时长。时长为 0 的未知视频不命中 `under30` 或 `custom`。

### 界面

时长下拉新增：

- `30秒内（≤30秒）`
- `自定义`

选择自定义后显示“最短秒数”和“最长秒数”两个数字输入框。输入无效时显示明确错误并禁止开始抓取。合法范围随任务 filters JSON 保存，任务暂停、恢复和程序重启后语义不变。

### 过滤位置

继续复用 `filterVideos` / `matchDuration`，在抓取结果进入数据库和下载队列前过滤，不把不符合范围的视频创建为待下载项。

## 封面下载

### 元数据

从抖音视频对象中按可靠静态图优先级提取首个可用封面地址：`video.origin_cover`、`video.cover`、`video.dynamic_cover`。每个字段沿用现有 `url_list` 取首个非空地址。

`VideoItem` 增加封面 URL 和宽高；`videos` 表增量增加：

- `cover_url TEXT`
- `cover_path TEXT`
- `video_width INTEGER NOT NULL DEFAULT 0`
- `video_height INTEGER NOT NULL DEFAULT 0`

所有写视频的路径，包括普通写入、调度器直接写入 filtered/collected/pending 的路径，都必须保持字段一致。

### 文件命名与下载

下载器先用现有安全命名和重名处理确定 MP4 的最终 basename，再让封面复用完全相同的 basename：

- `红烧肉.mp4`
- `红烧肉.jpg`、`红烧肉.png` 或 `红烧肉.webp`

若 MP4 因重名变成 `红烧肉_1.mp4`，封面必须是 `红烧肉_1.*`。封面扩展名按响应 `Content-Type` 选择，未知类型回退 `.jpg`。确定 basename 时同时检查 MP4 和可能存在的同名封面，不能覆盖孤立的旧封面文件。

封面使用现有 `fetchImpl`、相同 User-Agent/Referer 和下载中止信号，不另建网络客户端。封面下载失败不把已校验成功的视频改成失败；`cover_path` 保持空，并记录诊断日志，避免封面 CDN 波动阻断核心视频下载。

取消或暂停发生时，视频半成品和封面半成品都要清理。删除单条视频时，如 `cover_path` 位于下载目录内，也与 MP4 一起删除。

## 横竖屏归档

### 判定

优先使用抖音元数据中的 `video.width` / `video.height`：

- `height >= width`：`竖屏`
- `width > height`：`横屏`

若元数据缺失，归档前复用 `findBin('ffprobe')` 探测已下载 MP4 的第一条视频流宽高，并回写数据库。仍无法获得有效宽高时使用 `未识别`，不猜测方向。

### 目录结构

新目录层级固定为：

`品类 / 作者 / 竖屏|横屏|未识别 / 一分钟内|一分钟外 / 文件`

例如：

```text
美食/张三/竖屏/一分钟内/红烧肉.mp4
美食/张三/竖屏/一分钟内/红烧肉.jpg
```

视频与封面必须成对移动到同一目录。归档重名时以视频目标 basename 为准，封面跟随同一个重名后缀。MP4 移动成功但封面移动失败时，该条归档失败，避免数据库指向半套新旧位置；实现应在移动前算好目标并在失败时尽量回滚已移动文件。

`local_path` 与 `cover_path` 同步更新。现有 `durBucket` 保持一分钟内/外语义不变。

## 文件管理与兼容性

文件管理现有统计继续只计算 MP4 数量和 MP4 大小，封面不重复计入“视频数量”。删除品类或作者目录时，目录级删除天然包含封面；数据库按 `local_path` 前缀删除仍以 MP4 行为准。

旧视频行新增字段默认为空/0，可以继续展示和删除。旧任务没有新增 duration 字段时继续按原有筛选工作。已经在旧结构中且 `organize_state='done'` 的文件不自动迁移。

## 错误处理

- 自定义时长不合法：前端阻止创建任务；主进程 `matchDuration` 对不完整/非法 custom 条件返回不匹配，避免意外全量下载。
- 封面地址缺失或下载失败：视频仍可完成，`cover_path=NULL`，记录警告。
- 宽高缺失：ffprobe 兜底；仍失败进入 `未识别`。
- 成对归档部分失败：标记作者归档失败并保留可重试状态，不静默宣称完成。

## 测试与验收

自动测试至少覆盖：

1. `under30` 的 0、29、30、31 秒边界。
2. custom 的 10、20 两端包含，范围外排除，非法范围拒绝。
3. 筛选表单切换自定义、提交字段、错误提示和按钮状态。
4. 抖音封面候选、宽高解析及缺字段回退。
5. 老数据库自动补列，写入和读取新字段。
6. 视频与封面同 basename，重名后缀一致，封面失败不阻断 MP4。
7. 暂停/取消清理封面半成品，删除视频同步删除封面。
8. 横屏、竖屏、正方形、未知尺寸判定。
9. 视频与封面进入 `品类/作者/方向/时长`，路径同步更新且失败可重试。
10. 全量类型检查、测试、生产构建和 CSS 产物检查。

人工验收使用独立测试目录抓取少量 10–20 秒视频，检查任务实际只收录范围内条目，并确认 MP4/封面同名且横竖屏目录正确。
