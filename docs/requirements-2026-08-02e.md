## 1. 核心诉求（3 条，均已确认）

### ① 抖音窗口还是不出现（用户实测：完全没出现，测试 agent 排查）

- 现象：点「打开抖音窗口」/ 浏览器 tab / 抓取时，桌面**完全没有任何新窗口出现**（第四轮 everShown 修复后仍如此）。
- **排查方式**：测试 agent（Electron 窗口工程师）写**探针脚本在本机实机运行**——创建主窗口 + VideoBrowser，走真实显示路径（`setVisible(true)`），记录：`win` 是否非空、`isVisible()`、`getBounds()` vs `screen.getPrimaryDisplay().workArea`、IPC 链路是否到达。据此定位根因（嫌疑：首次定位把窗口放到屏幕外 / show 路径未到达 / 窗口被立即隐藏 / 异常中断），修复后探针复验 + 人工复测。
- 验收：点「打开抖音窗口」窗口真实出现在屏幕内可视位置；抓取/验证时同样出现；不抢焦点语义保持。

### ② 任务页参数保留（仅 tab 切换，已确认）

- 现象：切 tab 再切回，「任务」页的关键词/筛选规则/下载方式等输入全部清空（组件卸载）。
- 修法：**「任务」tab 内容（FilterForm + TaskList）常驻挂载**，切到其它 tab 时用 CSS `hidden` 隐藏而非卸载——参数、展开状态全部保留；TaskList 的进度订阅常驻（切回即最新）。
- 验收：输入关键词 + 筛选规则 + 下载方式 → 切「作者收藏/设置」→ 切回 → 参数原样在；重启程序后不要求保留（恢复默认）。

### ③ 下载暂停增强（两者都要，已确认）

- **全局暂停含在途中断**：点「暂停下载」时，正在下载的**立即中断**（AbortController 掐断），该条保持排队状态；点「继续」恢复下载。
  - 注：不做字节级 Range 断点续传（CDN 多数不支持/不稳定），"继续"= 重新下载该条，但队列位置与状态保留。
- **单条视频可暂停/继续**：视频表格每行加「暂停 / 继续」按钮——暂停：在途则中断、排队则出队，状态置 **`paused`**（新增 VideoStatus）；继续：置 `pending` 重新入队。
- 与既有取消/重试/全局暂停共存；`taskStats` 补 `paused` 计数；UI 状态文案补「已暂停」。
- 验收：
  - 下载中点全局「暂停下载」→ 在途立即停（不再等它跑完），点「继续」→ 恢复下载
  - 单条点「暂停」→ 该条停（其它继续）；点「继续」→ 该条恢复
  - 重启后 paused 项**不**自动下载（手动继续才下）
