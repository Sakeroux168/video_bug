## 1. 背景

第二轮验收全绿后，用户实测提出 5 项新反馈：窗口抢焦点盖文件、滚动仍快、选择语义再修、下载失败原因不可见、以及一个新功能（用抖音自带筛选续爬）。

## 2. 核心诉求（3 条，均已澄清确认）

### ① 窗口焦点 / 滚动速度 / 失败可视化

| 项 | 确认方案 |
|---|---|
| 窗口抢焦点 | 程序化显示抖音窗口一律 **`showInactive()`**（显示但不抢焦点）；stalled_verify 弹窗同样不抢焦点（toast + 任务行黄条提示，用户自己切到浏览器 tab）；删除抓取过程中的 `focus()` 调用 |
| 滚动速度 | 设置页加**「滚动速度」三档**（慢/中/快，默认慢）+ **数字微调「每页最大等待秒数」**（默认 8s）。慢=8s、中=5s、快=3s；档位改数字微调的初始值，数字直接生效。参数化 `scrollToBottom` 的 waitForGrowth 超时与轮询间隔、scheduler 的 settle sleep |
| 失败可视化 | 视频表格状态列显示**中文原因**（错误码→中文映射）；工具栏加**「只看失败」**开关筛选 |

### ② 选择交互语义（替换+框内翻转）

- **点行** = 排他：点未选中的行 → 只选它、清空其它；点已选中的行 → 取消它（结果全不选）。
- **框选** = 替换 + 框内翻转：框住的项全部成为唯一选择集，其中**已选中的翻转取消**、未选中的选中；框外一律取消。
  - 验证场景：先框选 1-5 → 再框选 3-8 → 结果只留 6-8。
- 点空白清空保持；与批量按钮（下载选中 N/取消选中 N/删除选中 N）计数兼容。

### ③ 抖音自带筛选续爬（新功能）

- FilterForm 加**「搜索到底后用抖音筛选续爬」**开关 + **4 个下拉**（全部可配，均含「不限」）：
  - 发布时间：不限 / 一天内 / 一周内 / 半年内
  - 视频时长：不限 / 1分钟以下 / 1-5分钟 / 5分钟以上
  - 搜索范围：不限 / 关注的人 / 最近看过 / 还未看过
  - 内容形式：不限 / 视频 / 图文
  - 存入任务 filters JSON。
- **触发**：搜索页滚动停滞（连续 2 轮无新内容且未达目标、且本任务**未应用过筛选**）→ 注入脚本自动操作：点筛选按钮 → 选配置项（「不限」的组跳过）→ 等页面刷新 → 重置停滞计数继续爬。**只应用一次**；应用后再停滞按原逻辑停。
- **选择器**（用户提供，抖音哈希类名，有变动风险）：
  - 筛选按钮 `span.bR4uhU1W`；面板 `div.IMWRHJOg`；选项 `span[data-index1=组][data-index2=选项]`（组：0排序/1发布时间/2时长/3搜索范围/4内容形式）；选中项带 `HjptjtzN`。
  - 选择器常量放抖音适配器（`FILTER_SELECTORS`），便于平台迁移/类名变动。
- **失败兜底**：选择器失效（点筛选后页面无变化/脚本报错）→ 不卡死，按原逻辑停，toast 提示「筛选续爬未生效（页面结构可能已变）」。
- **去重**：筛选刷新后靠现有 `seen` 集合自然跳过已爬过的，只收新内容。
