## 1. 这个项目是什么

一个给公司员工用的 Windows 桌面工具：在内置浏览器里登录抖音、快手（进行中：小红书），按**关键词 / 话题 / 作者主页**批量抓取公开视频的元数据，下载视频与封面，用 FFmpeg 统一转码成 1080×1920 规格，再按设置归档到文件夹，并可导出 CSV 表格。

使用者是非技术员工，拿到的是一个免安装的便携 EXE。

**用户（项目负责人）的工作方式**：想法常常先模糊地抛出来，希望先讨论再动手；重视界面好看、好用；拿真机日志、截图配合排查非常积极。

## 4. 架构

### 4.1 主链

```
平台浏览器（按平台切 session 分区，跨平台销毁重建窗口）
  → 注入脚本 buildInjectScript(adapter.rawUrlHints)，拦截页面自己的 fetch/XHR
  → window.postMessage('platform:raw')
  → src/preload/platform.ts
  → ipcMain 'platform:raw'（适配器取自 browser.adapter，不由 URL 反推）
  → scheduler.handleRaw
  → adapter.apiUrlPatterns 闸门
  → adapter.matchesTaskResponse(type, url, json)
  → adapter.parseApiJson → VideoItem[]
  → filterVideos / dedupeVideos → SQLite
  → Downloader → VideoNormalizer(FFmpeg) → Organizer（按层级归档）
```

**核心原则：我们不生成、不代发任何平台签名请求。** 页面自己请求，我们旁听响应。

### 4.2 关键文件

```
src/main/index.ts            主进程装配；拦截日志；任务队列 enqueueTask/dequeueTask/dequeueAndRun/kickQueue
src/main/browser.ts          VideoBrowser：ensureWindow(adapter) 按分区复用或重建；load() 吞掉 ERR_ABORTED
src/main/injector.ts         注入脚本生成
src/preload/platform.ts      页面消息 → IPC（原 douyin.ts 已删除）
src/main/scheduler.ts        任务循环、滚动、停滞自救、handleRaw 入库
src/main/adapters/types.ts   VideoItem 与 PlatformAdapter 契约
src/main/adapters/douyin.ts | kuaishou.ts | xiaohongshu.ts | index.ts（注册表）
src/main/downloader.ts       下载、封面、断点、地址过期回退、标准化
src/main/videoNormalizer.ts  ffprobe + FFmpeg
src/main/organizer.ts        品类/作者/横竖屏/时长 四层归档（每层可关）
src/main/filename.ts         文件名：只留标题、剥话题
src/main/videoSource.ts      作品链接白名单
src/main/ipc.ts | db.ts | settings.ts
src/renderer/src/App.tsx 与 components/（FilterForm、TaskList、FileManager、AuthorCollection、
    BrowserPanel、SettingsPanel、HelpPanel、videosCsv.ts 等）
```

### 4.3 PlatformAdapter 契约（当前）

```ts
interface PlatformAdapter {
  name; displayName
  taskReady: boolean             // false 时不进建任务下拉框（小红书现在是 false）
  sourceHosts; sessionPartition; homeUrl
  authorInputPlaceholder; downloadReferer
  apiUrlPatterns: RegExp[]       // 原始响应第一道闸门
  rawUrlHints: readonly string[] // 注入脚本只转发含这些片段的 URL
  buildSearchUrl / buildAuthorUrl / buildHashtagUrl / buildVideoUrl
  parseAuthorInput(raw); isShortLink(raw)
  matchesTaskResponse(type, url, json)
  parseApiJson(url, json): VideoItem[]
  normalizePlayUrl(rawUrl)
}
```

统一的 `VideoItem` 字段：`awemeId, title, authorSecUid, authorNickname, authorHomeUrl, playUrl, coverUrl, width, height, durationSec, publishTime(秒), likes, comments(可为 null), sourceUrl`。

### 4.4 调度器要点（任务 3 会动这里）

- `run(taskId)`：加载任务首屏 → 循环滚动；带停滞心跳与 `rescueStall` 自救（重搜冷却、到底探测）。
- `sleep()` 可被 `abortWait` 即时唤醒；`pause()` 会等 `run` 真正退出。
- `fetched >= target` 的判断分布在 `scheduler.ts` 约第 261、285、309、553、601 行。
- `handleRaw`（约第 519 行起）入库块：AI 过滤 → `upsertAuthor` → `INSERT OR IGNORE` → `fetched++` → 进下载队列 → 达标时 `abortScroll` → 推送进度。
- 队列只在 `task:done` 时放行下一个；删除任务走 `pause()` 不发事件，所以删除末尾要显式 `kickQueue`。

## 6. 快手：真机结论（最重要的教训）

**快手网页端不走 GraphQL。** 公开资料里的 `visionSearchPhoto` / `videoResource` / `photoUrl` 与今天的真机对不上。

| 用途 | 接口 | 方法 |
|---|---|---|
| 关键词/话题 | `/rest/v/search/feed` | POST |
| 作者主页 | `/rest/v/profile/feed` | POST |

```
{ result, webPageArea, pcursor, feeds: [...], llsid, searchSessionId }
feeds[i]: { type, tags[], photo{}, author{}, comment{} }
  photo: { id, caption, duration(ms), timestamp(ms), width, height, likeCount, viewCount,
           coverUrl, photoUrls:[{cdn,url}], photoH265Urls, manifest{...}, manifestH265 }
```

- 播放地址回退顺序：`photoUrl` → `photoUrls[]` → `manifest` 最高码率 H.264 → H.265。取不到整条丢弃。
- **快手不返回评论数**，`comments` 保持 `null`，界面显示「—」。**不要映射成 0。**
- 作者主页响应根结构未取样，判据锚在 URL + `feeds` 是数组。
- `__NS_hxfalcon` 是快手签名，页面自带，我们不碰。

**由此定下的铁律：先抓真机接口与响应，再写解析器。不照公开资料写。**

## 7. 小红书：当前进行中

### 7.1 用户的关键决定

- 用户明确选择 **「必须能下载视频文件」**。小红书的搜索列表只给卡片、不给播放地址，所以必须做**两段式**：列表拿存根 → 逐条导航到笔记页 → 旁听详情响应拿播放地址。
- 讨论过「开跑前先点小红书自带的『只看视频』筛选」：筛选**不体现在网址里**，内置浏览器也没有地址栏，且小红书 DOM 类名是哈希的，点按钮不可靠。结论是否决，改为在解析层丢弃图文。
- 讨论过「用 GitHub 现成轮子」：MediaCrawler 等是非商业许可，**不能抄代码**；许可兼容的项目（`xiaohongshu-mcp`、`Openweb`，需重新核对 LICENSE 与固定 commit）只参考思路。
- 用户愿意在控制台敲命令配合取证，之前两份抓包都来自用户本机。

**列表结构要点**：`items[i] = { id, model_type:'note'|'hot_query', xsec_token, note_card }`；`note_card.type` 为 `'video'` 或 `'normal'`（图文）；`interact_info` 全是字符串（含「1.2万」「3千」、空串）；没有播放地址、没有时长。实测未筛选时 20 条里仅约 1 条是视频。

**详情结构要点**：`data.items[0].note_card.video.media.stream.{EF4,EF5,EF6,EF7}[]`，每档有 `width / height / avg_bitrate / master_url / backup_urls`；`master_url` 带签名，`t=` 十六进制到期时间约 3.7 天；`time` 为 13 位毫秒；`video.capa.duration` 为秒；`media_v2` 是 media 的 JSON 字符串副本。实测样本 EF4 一档 720p，EF5 四档 720/1080/1440/2160p（2160p 单条 212MB）。

## 10. 红线（必须遵守）

1. 不绕过验证码；不做账号池、代理池、高并发。
2. 只抓公开内容。
3. 日志不打印 Cookie、签名、token、完整响应体。
4. 打开外部链接必须走适配器白名单。
5. 不用 `scale=1920:1080` 硬拉伸。
6. FFmpeg 失败不丢已验证的源视频。
7. 只删受管理下载目录内、经安全校验的路径。
8. 不自动搬迁已归档旧视频、不自动改名旧文件。
9. 不同时运行两个实例写同一 `%APPDATA%\video-scraper`（测试 EXE 用独立 `--user-data-dir`）。
10. 打包前必须跑许可检查；新增依赖必须登记。
11. 不把 Commons Clause 项目宣传为 OSI 开源。
12. 不覆盖稳定 EXE。
13. 接口字段是易变外部契约，解析失败要有明确诊断。
14. Tailwind 类名不动态拼接。
15. `ERR_ABORTED(-3)` 不是加载失败。
16. 不写无参兜底 `catch`。
17. **小红书 `xsec_token` 是短期令牌，不落库**；存库的作品链接不带 token。
18. 不抄 MediaCrawler 等非商业许可代码。
19. **先抓真机接口再写解析器。**
