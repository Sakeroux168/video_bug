## 起因

员工反馈下载目录里文件夹太多。原归档固定套四层 `品类/作者/横竖屏/时长`，同一个作者的视频只要有横有竖、有长有短，就会散进 4 个目录。

## 功能

1. 设置页新增「下载后分文件夹整理」，四个复选框互相独立：按品类 / 按作者 / 按横竖屏 / 按时长。
2. 勾几层建几层。路径顺序恒为 `品类/作者/横竖屏/时长`；关掉中间层只让路径塌陷，不重排剩余层。
3. 一层都不勾 = 视频直接平铺在下载目录，面板显示「当前：所有视频直接放在下载目录，不分文件夹。」
4. 默认值按安装情形区分：`settings.json` 存在即视为升级前老用户，四层全开、行为不变；全新安装四层全关。
5. 关掉品类层不再调用 `resolveCategory`（不产生 AI 调用）。关掉横竖屏层不再对缺尺寸视频跑 ffprobe。
6. 未启用任何层级时，手动「整理全部 / 整理作者」返回 `skipped`，界面提示「未开启任何分类层级，视频保持在下载目录里，无需整理」，不再显示读起来像故障的「已整理 0 个作者」。
7. 改设置只影响之后下载的视频；已归档文件不自动搬家。该说明同时写在设置面板和内置「使用说明」页。

## 实现中修正的两个缺陷

两处都是先由测试跑红暴露，再改实现，不是事后补写的断言。

1. **全关时把作者标 `organize_state='done'` 会把文件永久锁在根目录。** 用户关着层级下载一批，之后重新开启层级点「整理全部」时，`organizeAll` 按既有规则跳过 `done` 的作者，这批平铺文件再也归不了档。改为置回 `null`：`organizePending` 只认 `pending`（不空转），`organizeAll` 认 `null`（能补归档）。既有断言「organizeAll 跳过已 done 归档的作者」未被削弱或删除。
2. **全关时 `markAuthorPending` 照常标 pending 会让归档器反复空转。** 平铺文件永远满足「仍在下载目录根」的判断，作者会被每次下载重新唤醒。已在全关分支短路。

`Organizer` 的 `levels` 设为必填（非可选），使漏接线成为编译错误，而不是静默沿用旧的四层行为。
