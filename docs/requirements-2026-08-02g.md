## 1. 核心诉求（4 条 + 1 确认）

### ① 时长列全是 0（显示真实时长）

- **根因（已定位）**：`douyinAdapter.parseAweme` 只读顶层 `o.duration`（毫秒），但真实接口该字段名/位置不同 → 全部解析为 0；显示层 `formatDuration`（mm:ss）本身正确。
- **修法**：
  1. 时长解析**多候选兜底**：`o.duration ?? o.video?.duration ?? 0`（毫秒 → 秒）；顺带对 `o.video?.duration` 等候选字段名做防御。
  2. 解析结果为 0 时，在**拦截日志**（rawLog）里补一条提示（含该条目的顶层字段名列表），下次实跑即可看到真实字段名，若多候选仍取不到可再精准修。
- **验收**：实跑后时长列显示真实时长（如 0:08 / 1:23）。

### ② 筛选续爬第三次失败（先诊断，已确认）

- **修法（诊断先行）**：
  1. **全链路日志**：筛选续爬每一步写进日志（停滞判定 → 是否到底文案 → 15s 计时 → CDP attach 成败 → 按钮坐标 → 面板出现/超时 → 每选项点击 → 结果），日志走现有「查看拦截日志」面板（或新增"筛选日志"区块）。
  2. **「手动测试筛选」按钮**（调试区，App 头部或日志面板旁）：一键触发当前任务的筛选流程，用户可看着抖音窗口实时观察 + 看日志。
  3. 日志输出带上关键状态值（坐标、轮询结果、错误信息）。
- **验收**：用户实跑一次，把日志反馈回来 → 依据日志定位根因并修复（修复可能涉及触发时机/CDP 交互/选择器，本轮以拿到诊断信息为主）。

### ③ 文件管理：定位作者/品类

- FileManager 一级页每行加「定位」（`shell.showItemInFolder(品类路径)`）；二级页每行加「定位」（作者文件夹路径）。
- IPC：`files:locate`(path) → isPathInside 校验 → `shell.showItemInFolder`。
- **验收**：点定位 → 资源管理器打开并选中该文件夹。

### ④ 文件管理：总大小

- FileManager 顶部汇总行：**总大小**（所有文件合计，GB/MB 自适应格式化）；品类行显示各自合计（已有）；二级页顶部显示该品类合计。
- **验收**：总大小与各品类大小数字正确（与资源管理器属性一致）。
