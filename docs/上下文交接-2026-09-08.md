## 1. 快手：真机接口与原设计的出入（最重要的一节）

**快手网页端早就不走 GraphQL 了。** 交接文档 09-07 版与社区资料里的
`visionSearchPhoto` / `visionProfilePhotoList` / `videoResource` / `photoUrl`
这一套，对今天的快手网页端**不适用**。

真机实测（2026-09-07 / 09-08，拦截日志 + DevTools）：

| 用途 | 接口 | 方法 |
|---|---|---|
| 关键词/话题搜索 | `/rest/v/search/feed` | POST |
| 作者主页 | `/rest/v/profile/feed` | POST |

搜索响应根结构（实测）：

```
{ result, webPageArea, pcursor, feeds: [...], llsid, searchSessionId, host-name }
feeds[i]: { type, tags[], photo{}, author{}, comment{}, authorStatement? }
  author: { id, name, headerUrl, following, livingInfo }
  photo:  { id, caption, duration(ms), timestamp(13位ms), width, height,
            likeCount, viewCount, collectCount, coverUrl, animatedCoverUrl,
            photoUrls: [{cdn,url}], photoH265Urls: [{cdn,url}],
            manifest{adaptationSet[].representation[]}, manifestH265, ... }
```

关键点：

- **播放地址是 `photo.photoUrls[]`（数组，多 CDN 同内容），不是 `photoUrl`。**
  回退顺序：`photoUrl`（旧路由）→ `photoUrls[]` → `manifest` 最高码率 H.264
  → `manifestH265` / `photoH265Urls`。一条都取不到就整条丢弃。
- **这个接口不返回评论数。** `feeds[].comment` 只有 `us_c`，20 条样本全为 0
  （点赞 22 万那条也是 0），据此判定它不是评论数。`comments` 保持 `null`，
  界面显示「—」。**不要把它映射成 0。**
- 作者主页响应的根结构**未取样**。作者任务的判据锚在 URL 加 `feeds` 是数组；
  解析器按 `{ photo, author }` 形状取值、不依赖根字段名，真机已解析成功。
- `__NS_hxfalcon` 是快手的签名参数，我们不生成也不解析——页面自己带。


（抖音硬编码）；`src/preload/douyin.ts`。

## 4. 仍然有效的红线（沿用 09-07 版）

1. 不绕过验证码，不做账号池/代理池/高并发。
2. 只抓公开内容。
3. 日志不打印 Cookie、签名、token 或完整响应体。
4. 打开外部链接必须走适配器白名单。
5. 不用 `scale=1920:1080` 硬拉伸。
6. FFmpeg 失败不丢已验证的源视频。
7. 只删受管理下载目录内经安全校验的路径。
8. 不自动搬迁已归档旧视频、不自动改名旧文件。
9. 不同时运行两个实例写同一 `%APPDATA%\video-scraper`。
10. 打包前必须跑许可检查；新增依赖必须登记。
11. 不把 Commons Clause 项目宣传为 OSI 开源。
12. 不覆盖稳定 EXE。
13. 接口字段是易变外部契约，解析失败要明确诊断。
14. Tailwind 类名不动态拼接。

**本轮新增两条经验：**

15. **`loadURL` 的 `ERR_ABORTED(-3)` 不是加载失败**，是导航被取代或重定向。
    当成失败会白白判死任务。
16. **不要用不带参数的兜底 `catch`**。09-07 版遗留的 `catch { fail('network') }`
    让「浏览器一直转圈」排查不下去，真实原因被整个吞掉。
