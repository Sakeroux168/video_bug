# 需求文档：多平台视频批量爬取桌面程序

**日期**: 2026-07-31
**状态**: 已确认，待实施
**技术设计详见**: `docs/superpowers/specs/2026-07-31-douyin-video-scraper-design.md`

## 1. 背景与目标

用户需要一个**桌面程序**，内置浏览器登录视频平台后，按筛选条件批量抓取无水印视频到本地。首发抖音；架构要求扩展性强，后续可爬快手/小红书/TikTok/B站。可选接入云端 AI 做"下载前筛选"和"下载后整理"。

## 2. 核心诉求

1. 桌面程序：内嵌浏览器登录平台，关键词/作者/话题搜索 + 时间/时长筛选 + 目标数量 **200-1000 自定义**，批量下载无水印 MP4，实时进度、断点续传、风控自动暂停。
2. AI 分析（云端 API）：**下载前筛选** + **下载后分类打标签归档**，只分析文本元数据。
3. 强扩展性：平台相关逻辑隔离为**适配器**，为快手/小红书/TikTok/B站 预留。

## 3. 验收标准

- [ ] 启动 → 内置浏览器扫码登录抖音 → 登录态持久化
- [ ] 填筛选（平台/时间/时长/数量 200-1000）→ 触发抓取 → 任务列表实时进度
- [ ] 批量下载无水印 MP4 到指定目录，文件名带标题，去重
- [ ] AI 先审后下：按用户规则过滤，不通过不下载
- [ ] AI 下载后整理：自动分类归档到子文件夹 + 打标签
- [ ] 风控/网络/AI 错误正确分类提示，可断点续传、单视频重试
- [ ] 新增平台只加一个适配器文件，核心零改动（有接口 + 注册表）

## 4. 范围

### 做

- Electron + React + TypeScript 桌面程序
- 内置浏览器 + 页面注入 fetch/XHR 挂钩截平台内部 API（方案 A，绕过签名）
- 抖音适配器（首发）+ 适配器接口与注册表
- 关键词/作者主页/话题 三种抓取方式；时间/时长筛选
- SQLite 三表（tasks/videos/authors，含 platform 字段）
- AI 分析（OpenAI 兼容云端 API，可配地址/Key/模型）
- 下载目录、并发、AI 配置等设置项

### 不做（当前版本）

- 代理/多账号轮换、自动定时爬取、评论/封面导出
- 音视频内容理解（听语音/看画面）——AI 只分析文本
- 快手/小红书/TikTok/B站 的实际实现（只留适配器接口）
- 打包 exe 安装包（先 `npm run dev` 跑通）

## 5. 架构与数据模型草案

- 三层 + 平台适配层：渲染层 React ↔ 主进程（调度/解析/AI/下载/存储）↔ 内嵌浏览器（挂钩截流）
- `PlatformAdapter` 接口：域名/接口特征/URL构造/JSON解析/无水印规则/登录分区
- 数据表：`tasks`（platform/type/query/filters/status/target_count）、`videos`（联合唯一键 platform+aweme_id，ai_verdict/ai_tags）、`authors`（platform+sec_uid 唯一）

## 6. 任务拆分清单

1. 工程脚手架（electron-vite + React + TS + Tailwind + better-sqlite3 + Vitest）
2. SQLite 三表 + 封装
3. 平台适配器接口 + 抖音适配器
4. 内置浏览器 + 通用挂钩脚本 + 消息桥
5. 调度器 + 解析器（过滤/去重）
6. 下载器（无水印、文件名清洗、并发限速）
7. AI 分析器（OpenAI 兼容客户端，先审后下 + 分类归档）
8. IPC + 渲染层 UI（三标签、筛选表单、任务列表、作者收藏、设置）
9. 错误处理矩阵 + 断点续传 + 风控暂停恢复
10. 联调验证 + 成功标准逐条过

## 7. 其他约定

- 交付先 `npm run dev` 跑通，不打包
- AI 成本控制：只发文本、按 aweme_id 缓存、并发限 2、可整体关闭
- 风控优先：滚动间隔 1.5-3s 随机、下载并发 3、连续异常自动暂停
