## ④ 剩余缺口（按严重度排序）

1. **高｜TaskList 批量操作 UI 无端到端测试**：跨页选中集合、批量下载/取消/删除按钮的选中态过滤（`batch-pause-resume.test.tsx` 只测了暂停/继续计数），全选/本页全选的 indeterminate 复选框逻辑无断言。仅能人工验收：全选勾选后翻页、搜索过滤后批量操作的对象集合。文件：`src/renderer/src/components/TaskList.tsx`。
2. **中｜BrowserPanel / App 布局与筛选表单交互**：`BrowserPanel.tsx`（内置浏览器 iframe 显示/隐藏、小窗按钮）与 `App.tsx`（tab 切换、设置面板触发重建）无组件测试；`filter-form.test.tsx` 只覆盖目标数量与按钮位置。人工验收：真实浏览器内过验证码后点继续、任务恢复。
3. **中｜organizeAuthor 中 AI 分类与 ASR 的组合路径**：`organizer-ai.test.ts` 只有 3 条 classifyAuthor 单测；`organizer.test.ts` 的 resolveCategory 均为固定值/抛错桩，未覆盖「AI 分类回调耗时内作者重复 markAuthorPending」的竞态（实现里有去抖 + 幂等，但无并发测试）。文件：`src/main/organizer.ts`、`src/main/ai/organizer-ai.ts`。
4. **中｜download 失败后的 UI 重试/取消按钮组合**：failure-display 只测了展示；按钮组合矩阵（pending 行有「暂停/取消」、failed 有「下载/重试」、paused 有「继续」）由 video-delete.test.tsx 部分覆盖删除，其余无断言。人工验收：真实下载失败后点重试的行为。
5. **低｜injector.ts 页面钩子脚本**（fetch/XHR 拦截 postMessage）：纯字符串脚本无测试，实际依赖真实抖音页面；仅能人工验收（内置浏览器打开搜索页后「查看拦截日志」有数据）。
6. **低｜ASR 转写端到端**（`asr-media.test.ts` 3 条已真实跑 ffmpeg，但 transcribeFor→media 组合无测试；依赖本机 ffmpeg，环境相关）。仅能人工验收。
7. **低｜settings 面板 UI**（SettingsPanel.tsx 无组件测试）：滚动速度三档、每页等待秒数、地址 TTL 等字段的读写无断言。

## ⑤ 建议

1. **补 TaskList 批量操作矩阵测试**（缺口 1）：用现有 `selection.test.tsx` 的 stub 几何基建，把「全选 → 翻页 → 批量下载/删除」写成 3-4 条集成测试，这是唯一可能回归出「删错对象/批量对象丢失」的路径。
2. **organizer 竞态测试**（缺口 3）：fake timers 驱动 `scheduleOrganizeFlush` 去抖窗口，断言「多次 markAuthorPending 只归档一次」的并发安全——实现已有 guard，值得锁定。
3. **人工验收清单（建议随每次发版过一遍）**：a) 内置浏览器过验证码 → 点「继续」任务恢复；b) 抖音搜索页筛选面板实际点击生效（脚本路径真实 DOM）；c) 下载失败后重试/取消按钮组合；d) 页面钩子拦截日志有数据；e) ASR 转写一段真实视频。
4. **测试基建**：browser.test.ts（9.9s）与 scheduler.test.ts（6.2s）占全量一半时间，可考虑后续拆分或用 `--sequence` 串行跑 CI，但非本轮范围。
