## 1. 报告质量评估

**总体：B+。** 映射表颗粒度合理（行为级而非文件级）、缺口按严重度排序、补测数量与内容自洽（280→300 的 +20 均有文件名可核对），TDD 过程说明诚实。抽查 3 处缺口描述，发现 1 处不准确、1 处低估、1 处遗漏：

| 缺口 | 抽查结论（对照源码） |
| --- | --- |
| ① 高｜批量操作 UI | **描述不准确**：`tests/components/batch-pause-resume.test.tsx` 第 3 条已覆盖「跨页选中集合」（翻页后 `pauseVideos([1, 51])` 断言），并覆盖 disabled 禁用态——不是"只测了暂停/继续计数"。**真实缺口**是：a) 全选/本页全选勾选框与 indeterminate（`TaskList.tsx:526-531`，`ref` 回调里 `el.indeterminate = d.someOnPageSelected && !d.allOnPageSelected`，无任何断言）；b) 批量「下载选中/取消选中/重试选中失败」三个按钮的选中态过滤无测试（批量「删除选中」已被 `video-delete.test.tsx` 覆盖，报告的缺口 4 里也承认了这点）。补测范围应以这两块为准。 |
| ⑤ 中｜organizer 竞态 | **准确**。`scheduler.ts:396-409` 确有去抖（`scheduleOrganizeFlush`：`clearOrganizeTimer` + `organizeDebounceMs` 后单次 `organizePending`），`organizer.ts:75` 执行时重查 `isFlat` 天然幂等——竞态本身安全，但"多次 markAuthorPending 只触发一次归档"的去抖行为确实无测试锁定。 |
| ⑤ 低｜injector 钩子脚本 | **低估（误判为"仅能人工验收"）**。`src/main/injector.ts` 的 `INJECT_SCRIPT` 是纯字符串常量，jsdom 原生提供 fetch/XHR，直接 `eval`/`new Function` 求值后 stub `window.postMessage` 即可断言拦截（与 `tests/browser-click-options.test.tsx` 的"真实 jsdom 求值"同一模式）。可自动化，成本 3-5 条测试。 |

映射表无红色核心模块的结论经抽查属实；"没有红色"表述准确。

## 3. 人工验收清单处理建议（报告 ⑤.3 的 a-e）

固化规则：**人工清单只保留真实环境不可模拟项**；可自动化项一律转测试并移出必过清单。

| 项 | 处理 | 说明 |
| --- | --- | --- |
| a) 内置浏览器过验证码→点「继续」任务恢复 | **固化为每次发版必过** | 真实验证码不可模拟。但注意主链路（`stalled_verify` 提示行渲染、pauseTask/resumeTask 恢复）已有测试兜底，人工只验"真实浏览器完成验证"本身。 |
| b) 抖音搜索页筛选面板实际点击生效 | **固化为每次发版必过（最高风险项）** | 哈希类名每次发版都可能变（交接文档已知坑 1），自动化无法覆盖真实 DOM 失效。失效时用「手动测试筛选」按钮定位到 `[筛选]` 日志看候选命中。 |
| c) 下载失败后重试/取消按钮组合 | **自动化替代，从必过清单移除** | 归缺口 4（P0，本轮就补）；仅下载器改动时人工抽查一次。 |
| d) 页面钩子拦截日志有数据 | **自动化替代，从必过清单移除** | 归缺口 5（jsdom 求值）；仅 injector 改动时人工抽查。 |
| e) ASR 转写一段真实视频 | **保留人工，降频** | ffmpeg + 模型环境依赖，仅 ASR 相关改动后过，不必每次发版。 |

固化后每次发版必过清单 = **a + b**（原 5 项压到 2 项）。

## 4. 下一步测试投入建议（优先级排序）

1. **P0（本轮立即）**：TaskList 批量操作 + 行按钮矩阵（缺口 1+4 合并）——全选/indeterminate/翻页/搜索过滤后的批量下载/取消/重试 + failed 行按钮组合，3-6 条，复用 `batch-pause-resume.test.tsx` 的 setup 与 fake-api，预计 0.5-1 小时。这是唯一能回归出"批量对象丢失/操作错对象"的路径。

3. **P2（下轮）**：App tab 切换与任务页常驻挂载（缺口 2，2-3 条）；测试提速评估按 §2 暂缓。浏览器真实链路维持 §3 的人工清单 a+b。
